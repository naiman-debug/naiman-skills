# Git 收口

仅在 project-day-closeout 已产出本次 git_readiness 后使用本技能。

完整收工可以调用本技能完成已授权的本地提交。readiness_only 或 audit 本身不授权 Git 写入：前者只准备，后者只读。先核对当前调用目的、授权和本批 ready 状态，不能以 readiness 存在代替提交许可。

独立的“请提交本批变更”请求也可以先由主执行者运行 project-day-closeout 的 readiness_only 模式，再依据原 Git 请求进入本技能。此技能不自动启动 day-closeout；缺少 readiness 时只返回暂缓理由，避免递归调用。

准备步骤的 should_commit: false 只说明该步骤未提交，不取消另有的明确提交请求；主执行者必须保留原请求和当前授权。用户最新要求“只准备”“不要提交”时仍禁止提交，不静默把只读或准备请求解释为提交授权。

## 首次读取

1. 项目 AGENTS（存在时）。
2. 项目 profile（存在时）。
3. 本次 project-day-closeout 产出的 git_readiness。
4. Git 状态、相关 diff 与必要验证输出。
5. 项目已有 Git 收口规则；没有时读取[Git准备参考](references/generic-git-closeout-readiness.md)。

若 AGENTS、索引或 profile 缺失，可从 README、用户当前请求和本次 readiness 确定最小范围。缺失不授权创建项目规范、索引或 profile；在结果中说明覆盖限制。

## 执行流程

1. 确认本次 readiness 有效，本批准备就绪，并有完整收工或独立具名提交请求的授权。只有只读或准备请求时不暂存、不提交。
2. readiness 指出文件或目录必须先收口、必需验证缺失、文件仍在变化或归属不清时，暂缓受影响批次。
3. 按主题和风险建立批次；每批列出精确路径、验证依据和提交说明。
4. 暂存前检查 HEAD、暂存区和具名文件是否在检查后发生变化。
5. 只暂存获准批次中归属明确的文件。出现未知暂存项或并发改动时，保留现场并返回主执行者，不清空、不夹带。已存在的删除或改名变更，需另有具体授权、资格与恢复依据，并按准备参考完成必要例外核查；不合格路径暂缓，不在本技能里执行新的删除或搬移。
6. 对每个通过检查的批次完成本地提交；无变化不提交。
7. 提交后检查实际路径、提交号和残余变更，如实报告成功、部分成功或失败。

## 规则

- 不默认推送，也不执行 reset、clean、强制推送、历史改写或丢弃用户改动。
- 不暂存无关文件、未知暂存项，以及缺少具体授权、资格或恢复依据的删除和改名变更。
- 不因为提交前检查通过就替代业务验收；Git 检查只证明批次边界、验证依据和恢复条件。
- 无 Git 仓库、身份问题、锁、权限或并发问题时保留现场并返回清楚原因；不自动初始化仓库、配置身份或远程。
- 本次 readiness 是输入前提，不是反向调用 day-closeout 的安装依赖；完整收工组合仍由 day-closeout 声明并组织。
- 不回退到个人源目录或临时安装替代技能。依赖不可用时报告受影响项。

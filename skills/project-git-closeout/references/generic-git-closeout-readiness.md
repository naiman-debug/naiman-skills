# Git收口准备条件

项目没有更具体的Git收口规则时使用本参考；用户当前授权和项目已有约束优先。

## 暂存前必须具备

- `project-day-closeout`已产出本次`git_readiness`，本批允许提交。
- 独立的具名提交请求可使用刚完成的 readiness_only 准备结果，但提交授权须另外来自该请求；仅准备或只读请求本身仍不允许提交。
- 变更按主题分批，列出精确路径和归属。
- 必需验证已完成；仍未验证的层明确列出，不能用“已列缺项”代替通过。
- 受保护或敏感文件有相应授权，否则从本批暂缓。
- 已删除Markdown具备逐项资格、恢复依据和必要的例外审查；缺失时列为阻塞，不暂存该删除。
- 已有改名变更同时核对旧路径、新路径、引用影响和恢复方式；这些检查不授权在本技能内执行新的改名或搬移。

## 已有Markdown删除的检查

沿用以下字段，不因收工而执行新的删除：

```yaml
deleted_markdown:
  path:
  eligibility: eligible / blocked / needs_review
  recovery_proof:
  exception_review:
  absorbed_by:
```

项目规则允许时，普通已跟踪Markdown可引用具体版本及恢复方式作为依据。未跟踪文件、受保护文件、凭据、外部输入、法律/支付/SEO证据和原始来源不能仅凭“有Git”推断可恢复；blocked或needs_review的删除保持暂缓。

## 必须暂缓本批的情况

- 缺少本次收工的readiness，或调用模式只允许准备/检查；
- Markdown删除缺少资格或恢复依据；
- 未获相应授权的受保护文件被纳入暂存；
- 一个批次混入不相关变化或未知暂存项；
- readiness要求的必要验证仍缺失或失败；
- 提交前出现并发变化，原核验不再对应实际对象；
- 未经具体授权要求推送、reset、强制推送或改写历史。

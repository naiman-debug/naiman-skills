# 完整收工的各级索引对账

吸收项目初始化的持续登记原则；沿用项目现有职责和路径，不每次重新初始化。全部核对指声明的项目登记范围，不能以路径存在或Git干净证明索引完整。

## 发现范围与入口

从AGENTS、目录规则、总索引及局部入口沿引用发现，再在允许范围做轻量路径发现。按正文职责、元数据及关系识别总索引、局部索引/README、任务清单、结果JSON中的来源或产物清单、批次manifest；文件名仅作线索。重要产物单独登记，大量同类文件复用已有批次/来源清单，总索引引用其覆盖范围。

记录覆盖根目录、排除项及未读范围。依赖、缓存、Git内部与私密配置默认不展开；项目允许登记的被忽略产物仍须核对。外部项目仅核已声明的引用，不递归接管。源码可按模块和Git管理，不强制逐文件建账。

## 增量基准与实物

沿用既有索引/清单的核对时点、覆盖目录、排除项、登记路径或批次，以及可用的Git提交或清单版本。基准以来已提交、暂存、未暂存、未跟踪以及允许范围内被忽略的产物均需考虑。缺基准或覆盖不足时，对受影响目录做一次实际路径集合对账，复用现有记录保存核对范围与可解析基准；不新增每轮日志。

比较路径集合与登记覆盖，识别缺失、新增、额外和游离对象。数量相等不代表一致，修改时间也不能单独证明未变化。文件数、来源数、manifest行数、选集数各有分母、递归范围和时点；子集不重复相加。身份、当前revision、来源与采用关系按已有证据核对，不凭名称猜测，不默认增加哈希系统或重读全库正文。已有完整路径清单优先复用，确有覆盖缺口才补最小登记。

## 更新与传播

先分清当前登记、历史快照、混合文档和身份未定。混合文档只更新当前章节/字段；历史数值、接收状态及冻结回执原样保留。只有历史库存而无当前汇总时，在同一责任入口补最新核对结果或明确最新库存尚未核对。历史疑点记在现行责任记录，不追改原件。

路径不变但版本、状态、数量、采用或覆盖关系改变，也要同步受影响总索引、局部入口及当前清单。任务事实归任务记录，主线摘要归README，目录职责/规则变化才同步规范、AGENTS和修订依据。不复制完整业务日志或重写候选为已验收。

公共索引由一个维护者合并，写前回读并核对并发变化。另一任务仍在写入、未交接、归属不明或无读取权限时，登记观察范围、原因和返回位置，暂停受影响部分；不代替来源接收、不夹带提交其他任务变化。稳定批次可独立存档。

## 完成依据

逐入口给出已更新、核对后无需更新、历史保留或未核实/受阻，并保留覆盖依据。发现历史入口不等于核验历史内容；无需更新也须实际检查。覆盖不足时报告部分收口，业务未知已准确登记不阻止索引层完成。无实质变化不改日期、不新建收工日志、不空提交。按本轮最终实际状态回读，不因填写完成表就宣称执行成功。

维护规则时用四组案例推演：普通结果JSON承担清单且路径不变状态改变；等量增删及获准被忽略产物；当前/历史/子集混合统计；并发或权限受阻后的无变化重跑。仅涉及说明文字时做情境推演与实际项目只读演练；加入脚本或自动同步逻辑后才用临时样例运行正向及负向测试。

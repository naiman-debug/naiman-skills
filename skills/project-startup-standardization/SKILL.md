# 项目初始化与标准化

把项目从“材料已经有了，但入口、目录和责任不清楚”的状态，整理成能够继续工作的最小秩序。重点是发现和复用当前真值，不是套用固定文档体系。

## 适用条件

适用于新建项目的基础整理、已有项目的目录与材料盘点、原始输入归位、项目入口修订，或用户明确要求建立索引、来源关系、版本与历史边界。

先确认项目根目录和本轮目标。若项目有 AGENTS、README、目录说明、索引或其他责任文件，先读取与本轮有关的部分并沿用其职责。若缺少 AGENTS、索引或 profile，可从 README 和用户当前请求确定最小范围；缺失本身不授权创建这些文件，也不代表项目没有规则。把未覆盖的范围和未知事实写清楚，不编造项目规范、阶段、版本或授权。

## 工作方式

1. 恢复当前入口和范围。找出用户正在推进的结果、已有材料的责任位置，以及本轮可读和可写的路径。没有稳定入口时，先说明观察到的材料和候选入口；只有用户授权写入时才建立新入口。
2. 盘点当前材料。按本轮范围区分原始输入、源码、生成过程、中间结果、交付物、缓存和历史资料。无法读取的二进制、压缩包或受限文件只登记可见事实和限制，不猜测内容。
3. 设计最小秩序。优先复用现有目录和文档。需要持续追溯时，在已有索引、README、清单或其他责任文件中保存重要对象的路径、用途或状态、来源或生成过程、当前与历史关系，以及何时需要更新。小项目不必为此新建独立数据库、全套文档或逐文件台账。
4. 在授权范围内写入。只创建当前结果马上需要的目录、说明、索引或模板。README 常常适合作为工作入口，但不是所有项目的强制结构。AGENTS、项目规范、任务记录、profile、批次清单和元数据都按项目需要选用。
5. 回读并汇报。检查实际写入、相对链接、引用关系和索引覆盖范围。区分已完成、仅建议、未知和需要后续确认的事项。

## 来源、身份与历史

原始材料应保留原文或可靠定位方式，不能因整理而悄悄改写为当前结论。重要输入、跨步骤复用结果和交付物需要能说明来源；未知来源明确标为未知。

当版本、批次或恢复会影响判断时，为重要对象选择稳定标识和清楚的当前/历史关系。文件和目录名遵循项目既有语言与生态约定；避免用含义不明的名称猜测哪个文件有效。普通文档不必强制使用固定 YAML 字段、精确到分钟的时间或统一的状态词。

## 写入与收口边界

- 既有项目规则、用户当前请求和明确授权优先于本技能的通用建议。
- 未经具体授权，不批量移动、改名、归档或删除存量文件；涉及这类动作时先列出精确对象、影响和恢复方式。
- 不因为建立目录秩序而实现尚未确认的功能、配置外部服务、发布、付费、发送信息或提交 Git。
- 保留其他任务的改动和原始证据。发现无关问题只记录有接续价值的线索，不借机扩大本轮工作。
- 建档结果只能证明本轮整理和回读范围，不能代替业务验收、真实运行或用户验收。

## 可选模板与参考

仅在项目确实需要相应载体时使用模板。模板不要求一次性生成，也不要求保留全部字段。普通项目先复用现有入口；空目录则从用户已确认的目的开始，获准后才建立最小入口，不要求先有 README。

项目规范与当前规范是可选的同类起点，不同时生成两套规则；当前索引与产物登记按实际追溯需要选用，不重复登记。产物登记、批次清单、生成与维护中的ID、revision和运行记录主要面向多版本数据生产，不是所有项目的默认要求。只有实际发生需要持续维护的扩展、冲突或修订时，才考虑对应记录模板；已有任务记录能够承接时继续使用它。

- [AGENTS 模板](assets/templates/AGENTS.md)：为需要协作说明和读取导航的项目提供可裁剪起点；不依赖其他技能或固定模型。
- [项目规范、索引与来源模板](assets/templates/)：用于目录职责、重要产物、批次或冲突需要长期维护时。
- [通用规则切片](references/core-rules.md)：需要决定目录、版本、索引和清理边界时读取。
- [内容生产适配](references/content-engine.md)：处理内容批次或来源链时读取。
- [网站与应用适配](references/web-app.md)：处理框架目录与运行产物边界时读取。
- [案例：健身应用](references/case-fitness-app.md) 与 [案例：内容批次](references/case-content-engine.md)：仅作教学示例，不构成项目授权。
- [参考来源](references/sources.md)：框架或数据流程细节需要核对时使用。

## 汇报

说明本轮实际覆盖的目录和材料、采用或保留的入口、已更新的责任文件、来源与索引的覆盖情况、没有处理的未知项，以及下一步从哪里继续。输出语言跟随用户或项目约定；任务情况卡、固定表格和繁复元数据只在项目已有格式或用户需要时使用。

## 完成判断

只有在已授权的文件写入并回读后，才能说明本轮整理已经完成。完成建设至少要让后续使用者能从明确入口找到：目录职责，以及重要材料或产物的索引、来源和状态（这些信息可以合并在一个责任文件中）；还要说明由谁或什么流程在何时维护。若本轮只完成盘点或提出建议，应如实报告“已完成调查，未完成建设”。

若 AGENTS、索引、profile、历史材料或部分目录缺失或未核实，报告其对覆盖范围的影响；不要把可继续工作或静态检查通过写成完整项目治理或业务验收。

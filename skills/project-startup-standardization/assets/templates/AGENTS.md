## 读取顺序

1. 本文件（如存在）。
2. 项目 README 或实际工作入口。
3. 与当前任务有关的需求、规范、索引、任务记录或目录说明。
4. 只读取解决当前任务所需的历史材料。

若某个入口不存在，使用其他现有入口和用户当前请求确定最小可执行范围；空目录直接从已确认目的开始，并在结果中说明未覆盖部分。不要因为缺少入口而自动创建项目规范、索引、profile 或任务台账。

## 工作边界

- 当前动作服务用户已确认的结果；新消息先判断是补充、纠正、提问还是目标变更。
- 写入前确认目标路径和已有授权。删除、迁移、覆盖、外部发送、发布、付费或其他难以恢复的动作，需要有具体对象和明确授权。
- 保留无关改动、原始输入和未知文件。无法判断时说明限制，不假装已经核实。
- 按改动风险做必要回读、链接检查或针对性验证；文件存在、测试通过或审查结论各自只证明其覆盖层级。
- 稳定任务结束后更新受影响的既有责任文件；没有实际变化时不制造重复记录。

## 协作与交接

根据任务复杂度和用户可用的模型、工具与权限决定是否委派。主执行者负责目标、授权边界和最终整合；被委派任务应说明负责范围、可写路径、验收和返回位置。简单任务无需为了角色齐全而增加协作者。

需要跨会话接续时，在已有责任文件中保存真正影响继续工作的阻塞、已做与未做、结果位置和下个动作。项目没有这种载体时，只在确有接续需要并获得授权后建立最小记录。

# 网站与APP适配切片

## 通用映射

沿用实际框架的初始化结构，给每类目录补职责和生命周期。不要为了统一全部项目而把框架源码硬塞进另一套模板。
分别说明源码、测试夹具、公开静态资源、运行数据、构建输出。环境配置只列名称和获取方式。

## Next.js示例

官方约定：app/pages承担路由，public提供静态资源，src可选。
本技能建议：业务使用App Router时沿用app或src/app；测试数据留在测试区，SEO中间文件留在私有数据区，只有明确需要公开的静态资源才进入public。
文档、运行批次和交付登记各一个入口；没有数据生产流程时不创建data/runs。
案例：新增落地页写入路由目录，截图/检查报告写入具名验证批次，不把报告散在项目根。
源码文件跟随Git，单独登记发布包或重要设计产物，不为每个组件发一个产物ID。

## Flutter示例

Flutter官方指南按UI层和数据层划分职责，包含view/view model/repository/service。
本技能据此建议在项目既有lib结构中标注职责；保留框架生成的平台目录。test用于测试，构建输出按所选工具实际目录记录。
案例：一个页面变更由源码提交跟踪；安装包登记ID、版本、构建来源和目标环境。存在安装包不代表已上架。
小APP不为套架构模板强行创建大量空模块。

## 技术栈尚未定

先完成目录角色和文件秩序的通用部分，把依赖选型的实际路径标为暂定。
只询问会改变布局的选择；完整PRD、登录和支付细节不是建立文件秩序的先决条件。
版本相关细节在使用时核对框架官方文档，来源见[sources.md](sources.md)。

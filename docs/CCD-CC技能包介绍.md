# CCD-CC 技能包介绍

让 AI 帮忙做项目时，任务一旦需要交给另一个 AI，或者需要有人检查结果，就会遇到一些具体问题：交给谁、允许改哪里、做到什么程度算完成，以及检查发现问题后由谁处理。如果这些事情没有说清楚，协作可能变成反复解释需求，也可能出现顺手改了无关文件、自己检查自己却声称“独立审核”的情况。

CCD-CC 是一组用来约定 AI 分工、执行范围和复核方式的技能。它帮助你在需要协作时，把任务交清楚、把结果接回来，并判断现有验证是否足够。简单任务仍可以由当前 AI 直接完成，不需要每次都启动整套流程。

## 四个技能分别做什么

| 技能 | 什么时候用 | 帮你解决什么问题 |
| --- | --- | --- |
| 任务门禁 `ccd-cc-task-gate` | 拿不准一项工作是否需要独立复核时 | 判断当前 AI 自检是否足够、是否需要另一位检查者，或是否缺少关键授权和信息 |
| 受控代码执行 `ccd-cc-bounded-code-worker` | 要把一个明确的代码任务交出去时 | 说清允许修改的文件、不能碰的区域和完成标准，要求执行者做相关测试并检查是否越界 |
| 按需复核 `ccd-cc-review-loop` | 已有方案、文档或代码，需要另一个视角检查时 | 按“审查、修订、验证、结论”处理问题，默认一轮，不为凑一个通过结论反复循环 |
| 协作链 `ccd-cc-chain-orchestrator` | 工作确实需要多个阶段或跨会话交接时 | 为每个阶段明确负责人、交付物和验证方式，最后由一个负责人汇总结果 |

## 怎样使用

例如，你想把一个小故障交给执行者修复，可以这样说：

```text
使用受控代码执行技能，修复这个导出错误。
只允许修改导出模块和相关测试，不改其他功能。
完成后说明改了什么、测试结果如何，不提交或推送 Git。
```

如果只是想检查一份方案，可以说：

```text
使用 CCD-CC 按需复核，对这份方案做一轮独立检查。
重点看有没有遗漏需求或扩大范围，先给审查意见，不修改文件。
```

按当前需要选择一个技能即可。只有工作真的需要分阶段交接时，才使用协作链把它们组织起来。

## 使用前需要知道

这些技能提供的是工作指令，不会自动安装或连接 Claude Code。明确要求 Claude Code 参与时，需要真实可用的调用通道；通道不可用时应如实说明，不能把当前 AI 的执行说成 Claude Code 完成。同样，当前 AI 自己换几个角色检查，仍然属于自检，不能称为独立复核。审查意见也不能代替实际测试或用户对发布等操作的授权。

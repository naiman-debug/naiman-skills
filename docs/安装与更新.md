# 安装与更新

这里介绍固定版本的手动安装。公开仓库为 [naiman-debug/naiman-skills](https://github.com/naiman-debug/naiman-skills)，实际可下载版本从 [Releases](https://github.com/naiman-debug/naiman-skills/releases) 进入并下载 Source code (zip)。`0.1.0` 的预发布说明见 [RELEASE_NOTES.md](../RELEASE_NOTES.md)，实际状态以版本页为准；版本页没有相应条目时，不要把候选源码或一直变化的主分支当成已经验证的发布版。

本地预览时，可以把当前仓库当作解压后的目录，从其中的 `skills/` 按下表取出副本。这样试用的是本地候选内容，不是已经正式发布的版本。

## 先选择需要的技能

| 需求 | 必须复制的完整目录 |
| --- | --- |
| 只用项目建档 | project-startup-standardization |
| 使用打完收工或Git收口 | project-day-closeout、project-directory-closeout、project-git-closeout，同一发布版本的三项一起安装 |
| 只整理具名目录 | project-directory-closeout |
| 使用步步高讨论方案 | bubugao（含随包上游参考与许可，无需另装原版依赖） |
| 使用首页列出的全部技能 | 上述五项 |

每个目录都要包含 SKILL.md 以及它原有的 agents、references、assets 等内容；不是只复制一个 Markdown。无需安装本仓库之外的状态同步或边界控制技能。

## 选择安装位置

推荐第一次先在练习项目中安装，确认效果后再决定是否全局使用。

| 范围 | 位置 | 影响 |
| --- | --- | --- |
| 仅练习项目 | 项目根目录下的 `.agents/skills/` | 从该项目使用；不要同时在用户级安装同名副本 |
| 当前电脑用户 | 用户主目录下的 `.agents/skills/` | 可供多个项目使用 |

Windows 的用户主目录可以在资源管理器地址栏输入 `%USERPROFILE%` 打开；macOS/Linux 通常用 `~` 表示。目录不存在时可创建。安装后应类似：

```text
.agents/skills/
  project-startup-standardization/SKILL.md
  project-day-closeout/SKILL.md
  project-directory-closeout/SKILL.md
  project-git-closeout/SKILL.md
  bubugao/SKILL.md
```

这是安装目录结构，仓库中维护的源文件则放在 `skills/`。

Codex会发现本地技能变化；如果没有出现新技能或新版，重启Codex后再试。同名技能不会自动合并，应避免在多个发现目录保留同名副本。这些路径及重新加载说明依据[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

## 安装步骤

1. 下载并解压选定版本到技能安装目录之外，保留完整下载包和 LICENSE。
2. 检查目标目录是否已有同名技能。如果有，先走下方“更新”，不要点击合并覆盖。检查项目级和用户级两个位置。
3. 从下载包的 `skills/` 中复制上表指定的完整目录。不要复制仓库根目录的 AGENTS.md、个人配置或整个仓库到技能目录。
4. 打开安装后的 SKILL.md，核对开头 metadata.version 与所选版本一致；依赖技能也要核对。版本字段是标签，不能证明本地文件未被修改。
5. 在练习项目中明确输入所安装技能的名称：`$project-startup-standardization`、`$project-day-closeout` 或 `$bubugao`，并要求“这次只讨论或检查，不写入”。请Codex报告实际读取的SKILL.md路径，确认没有用了另一份同名技能。
6. 读完检查结果，确认范围后再试写入。使用Git功能前，练习项目应有可用Git与提交身份；技能不会自动初始化仓库或配置身份。

完整下载包保留 MIT 许可；若把单独技能再次分发，应把根 LICENSE 随包附上。首次安装不需要执行来自本仓库的安装脚本，本仓库也没有自动更新服务。

步步高还须保留目录内的 `LICENSE.upstream` 及完整 `references/upstream/`，其中包含 Matt Pocock 原版的访谈、术语与决策记录指令。步步高用 `$bubugao` 调用；若另外安装了原版“边聊边记”，其调用名为 `$grill-with-docs`。两者是不同技能，本仓库提供的是增加 Road 和 Context 适用性检查的步步高。

包内三个上游参考入口采用 `UPSTREAM-SKILL.md` 文件名，以免被当作额外技能发现。如果试用过仍使用嵌套 `SKILL.md` 的旧候选，按下方步骤完整替换目录，不能合并覆盖并留下旧入口。

## 更新已安装的技能

**GitHub更新、下载新版和更新安装副本是三件事。** 对另一个下载目录执行 `git pull`，不会更新已复制的技能。

1. 查看新Release的变化说明，确认是否改变触发条件、写入行为、依赖或使用方式。
2. 结束正在使用该技能的任务。对自己改过的技能先比较差异并保留修改，不能拿上游新版直接覆盖。
3. 将本次要更新的旧技能完整移动到一个备份目录。备份必须位于所有 `.agents/skills` 等技能发现目录之外，避免备份继续被识别。
4. 将新版完整目录复制到原位置。收工三件套一起更新；不要混合两版文件，也不要碰其他技能。
5. 按安装步骤核对路径、版本和只读调用，再在练习项目验证本次变化。确认可用后，旧版备份由你决定保留多久。

如果更新中断，先保留现场；缺少某个依赖时不要宣称更新完成。可以恢复旧版整套，再重新开始更新。

## 回退与移除

新版不合适时，结束相关任务，将新副本移出技能发现目录，再把之前备份的完整版本放回，按同样步骤确认加载路径与行为。若之前没有自定义修改，也可重新下载原Release恢复。

不再需要时，把对应技能目录移出发现目录即可；若其他技能仍依赖它，应一起处理或停止使用相关功能。

**退回或移除技能，不会撤销它过去生成的项目文件或Git提交。** 那些项目成果应按各自项目的恢复方法处理，不能靠换技能版本自动撤销。

## 目前支持到哪里

目标为Codex的本地技能方式，尚未提供插件市场安装、自动更新或其他客户端适配。受控环境已验证五个选定入口的干净宿主发现、桌面新任务对候选路径的显式读取和三个主技能调用及独立复核，以及整套更新回退的文件层和后续调用。独立 CLI、当前嵌套路径的自动发现、其他操作系统，以及从实际 Release 下载后的独立试装仍未验证；最后一项只能在版本页出现后进行。当前版本的实际测试范围见[项目记录](项目记录.md)，不要把文档支持路径当成所有设备都已实测。
